Git - is a VCS(version controlling system /source control)

intially git is not tracking the folder 
check - git status

do -git init in the folder you wanna do version control 
    (Initialized empty Git repository)
    (.git/ folder hidden folder)

U - untracked( git enable but untracked)
for track =>  git add file.txt  (A - track)
              git add . (for adding to track all at once)

M -Modified file (not in staging area)

git diff (Checking the differences made till last addition)

git commit -m "add initial code"   (adding commit)

git log (track of all commits with there commit id's)
        (with author name & email , date & time)
git log --oneline  (show all commits in short readable format with small sha(commit id))

git show <commit_id>  (show deeply what are the changes made in the specific commit)

git blame <file_path>  (check who has changed a part of content in a specific file and when also)




            [modified file] => git add <file_name>  => [staging area]  => git commit -m "message" => [commit all the changes are in staging area only]

            head => latest commit node (head points to some commit_id)    

            => if current commit have some bug and wanna make head point to last(or a specific commit) commit than comes
            the concept of REVERT BACK

            git reset --hard <commit_id>  (head goes to commit_id ,removes all after this commit(because these are lnearly connectd))

            removing one specific commit code/changes only than -
                                                                 => git revert <commit_id>
